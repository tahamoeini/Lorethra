# L-05 Scene Command Gateway Handoff

- Enhancement ID and user outcome: L-05; create, edit, progress, archive, retrieve, and promote StoryScenes through Lorethra's canonical write architecture.
- Status: implemented and focused-verified; documented as DONE. UI acceptance remains in L-09.
- Explicit implementation scope and exclusions: schema-validated scene draft creation, revisioned edits, activation/completion/cancellation, explicit reopen, archive/unarchive, branch-scoped reads/history, fork compatibility, and child-to-parent fast-forward promotion. The existing command envelope and `CommandGateway` remain the only scene write path. Cross-domain reference resolution, participant/interaction model work, immutable snapshots, UI, asset remapping, and data conversion are excluded.
- Evidence and current source paths: `backend/lke/core/commands.py` (command dispatch, write and read methods, branch snapshot/promotion); `backend/lke/core/story_scene_contract.py` (runtime schema validation); `backend/lke/api/app.py` (studio data and scene read routes); `schemas/contracts/scenes/scene.v1.schema.json`; `schemas/contracts/registry.json`; `tests/unit/test_story_scene_commands.py`; `tests/unit/test_story_scene_persistence.py`; `docs/contracts/COMMAND_CONTRACTS.md`; `docs/contracts/DATA_MODEL.md`; `docs/contracts/SCENE_DOMAIN.md`.
- Existing capability versus precise gap: schema v21 already persists stable scene identity and immutable scene revisions. L-05 connects those records to validated application commands and retrieval. Nonempty location, participant, interaction, memory, context-manifest, and history references are rejected until their owning records can be resolved and scope-checked in L-06.
- Proposed journey and acceptance criteria: an authorized user creates a draft under an existing adventure, optionally selects its scene sequence, edits an unarchived draft/active scene with an expected scene revision, changes lifecycle state through explicit commands, archives completed/cancelled scenes, and retrieves current state/history within the selected workspace, branch, and adventure. Stale revisions and invalid payloads fail without partial canonical writes. A fork starts with the latest parent scene state; a changed child scene is appended to the unchanged parent as a new revision with source lineage on promotion, while the child history remains intact.
- Module ownership and contract changes: scene rows remain canonical SQLite state. `CommandGateway` owns validation, revision append, command result, audit/outbox and branch revision behavior. The runtime validator loads the registered versioned contract. The API adds scene listing, detail, and revision-history reads; writes continue through the existing command endpoint. `jsonschema` and `referencing` are runtime dependencies so packaged gateway execution can validate the same contract; the sidecar build scripts include these packages and schema files.
- Canon, workspace, branch, actor and time constraints: scenes must belong to an existing adventure in the selected branch and inherit that adventure's pinned world reference. IDs are branch-local; scene sequences are unique within an adventure. Every mutation checks `expected_scene_revision`; edits preserve immutable identity/world/creation fields. AI actors cannot create or mutate scene records. Scene revisions record the canonical branch revision that committed them. No-op edits or repeated lifecycle values do not append scene or branch revisions.
- Source provenance, privacy and cloud consent: full scene documents and history remain in the local canonical database. Scene revisions store their committing branch revision. Promotion adds origin branch, source branch revision, and source scene revision lineage. This slice adds no provider, cloud transfer, or export behavior.
- Migration, backup, rollback and asset recovery: L-05 makes no schema migration. Commands use the gateway transaction, so validation or persistence failure rolls back canonical rows and associated revision/audit/outbox state. Existing backup inclusion of both scene tables is unchanged. Promotion appends into the target branch and retains the source branch records. No scene assets are created or remapped here.
- Dependencies and unresolved decisions: L-06 owns participant/interaction ownership and scoped references; L-07 owns immutable snapshots; L-09 owns the Scene Studio UI. API route runtime behavior remains unverified because FastAPI is unavailable in the current environment. The regular backup test module cannot import because Pillow is unavailable; the scene-only backup test can run with a placeholder for unused image functionality.
- Verification performed, exact results and limitations: Python 3.13.16 focused suite passed 21 scene-command, persistence, migration, and branch-promotion tests; five registered contract-schema tests and five existing adventure-library regression tests passed. The scene-only backup/restore round trip passed with a placeholder module for unused Pillow image functionality; normal test-module import fails because Pillow is absent. `compileall` passed for the changed gateway, schema validator, and API files. API/browser and packaged-sidecar runtime behavior were not verified because FastAPI is absent; the full backend baseline remains partial.
