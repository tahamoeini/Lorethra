- Proposed journey and acceptance criteria: a user creates or revises a scene through the existing command gateway; existing participant entities and NPC profiles are linked without copying canonical profiles; missing state remains `not_captured`, `{}`, or `null`; recorded dialogue cites immutable turn/edit content; action beats retain actor, target, action, intent, emotional beat, ordinal, and source references. Invalid scopes or stale references fail without partial revision/audit/outbox writes. Fork and promotion preserve already validated references with explicit branch lineage.

SQLite migration v22 rebuilds only the scene revision table's payload check, retaining both v1 and v2 and preserving existing rows.
- Canon, workspace, branch, actor and time constraints: AI actors cannot write scenes. Entity/NPC/location/asset references are workspace, adventure, and branch checked. Turn/edit references use exact content hashes. Scene revisions remain append-only and branch-local. Unchanged location, NPC-profile, and state references remain usable when their mutable owners later change; those owner records are not duplicated into the scene.
- Source provenance, privacy and cloud consent: no provider or cloud transfer was added. Participant knowledge scope is metadata using the existing shared/actors/author/private vocabulary; it does not override Context Engine authorization. Dialogue remains in immutable story turns. Scene action and emotional beats do not become canon by themselves.
- Migration, backup, rollback and asset recovery: schema v21→v22 migration is transactional and preserves existing v1 rows; a migration test reopens an upgraded database, checks the exact legacy JSON and foreign keys, and verifies the new immutable trigger. Existing backup/restore already includes the scene tables; no scene assets or profile copies are introduced. Failed gateway writes roll back with the ordinary command transaction.

NPC profiles and map-location rows are mutable and do not expose historical profile/location versions, so the scene retains validated entity/location references but cannot reconstruct the historical owner record's former contents. Knowledge-scope metadata is not yet consumed by context compilation. FastAPI and browser behavior remain unverified.
